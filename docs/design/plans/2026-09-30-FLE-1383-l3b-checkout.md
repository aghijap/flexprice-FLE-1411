# L3-B — Pay-first checkout conversion — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL at execution: superpowers:executing-plans, TDD each step. Scoping plan — do a fresh exploration pass of the checkout paths before implementing.

**Goal:** For checkout-gated flows (the customer pays *before* finalization), convert the draft and compute tax **when the checkout session is created**, so the payment link shows the final billing-currency amount and the payment record inherits the billing currency.

**Architecture:** Insert the same convert+retax step from L3-A into the two checkout draft-build paths, **after compute and before the payment record is created**. Finalize then skips conversion because `fx_conversion` is already set (guard added in L3-A). Add an open-checkout-session lock on billing-currency changes.

**Spec:** ERD §5.6, §8.2 (open-session lock), §8.4 (converted checkout draft frozen).

**Depends on:** L3-A (schema, `ConvertInvoice`, `fx_conversion`, finalize skip-if-set). Stacked on `feat/FLE-1383-l3a-conversion`.

## Global Constraints

- **Order is load-bearing:** conversion must run before the payment record is created — `CreatePaymentForCheckout` copies `req.Invoice.Currency` (verified `payment.go:914`) and `AmountDue` (`:913`). Convert first, or the payment is minted in the charge currency against a to-be-INR invoice.
- Reuse L3-A's `ConvertInvoice` + `ResolveRate`; do not duplicate conversion logic.
- No rate ⇒ **session creation fails**, nothing charged (name the pair).
- The converted checkout draft is **frozen**: recompute and manual line edits rejected so the paid amount cannot drift from the link.

## Review Focus

- **Both checkout entry paths** convert before payment: one-off checkout (`invoice_checkout.go:startCheckoutOnOneOffInvoice`, between `ComputeInvoice` and `StartPayFirstCheckoutSession`) and subscription/addon/qty/top-up (`checkout_session_actions.go:executeCheckoutAction` → `buildCheckoutDraftInvoice` in `checkout_session.go:674`, after `ComputeInvoice`/`RecalculateTaxesOnInvoice`, before `createCheckoutPayment`).
- **Auto-finalize path** (`payment_processor.go:768-791`) finalizes a fully-paid draft; it must skip conversion (fx_conversion already set) and the existing currency guard (`:740-750`) passes because the payment already inherited INR.
- **`ReconcilePaymentStatus` allows `amount_paid` on a DRAFT** (`invoice.go:2074/2104`) — so a pay-first draft carries `amount_paid` before finalize; L3-A's "convert only when amount_paid==0" must not block it (conversion already happened at session creation).
- **Rate fixed when the link is shown** — a rate edit after the link is created has no effect on that invoice.
- **Expiry/void cleanup** returns any pending wallet credits (ties to L3-C top-up).

## File Structure

- `internal/ee/service/checkout_session.go` — convert in `buildCheckoutDraftInvoice` (after tax, before payment); `invoice_checkout.go` — convert in the one-off checkout path.
- `internal/ee/service/customer.go` — extend the §8.2 guardrail: block billing-currency change while an open checkout session exists (new customer-scoped active-session lookup via `CheckoutSessionRepo.List` with `CustomerIDs` + `types.ActiveCheckoutStatuses()`).
- Invoice recompute / line-edit entry points — reject on a converted checkout draft.

## Tasks

### Task 1 — Convert in the subscription/addon/qty/top-up checkout path
In `buildCheckoutDraftInvoice`, after `ComputeInvoice` + `RecalculateTaxesOnInvoice` and before returning to `createCheckoutPayment`: if the invoicing customer has a differing billing currency, resolve + `ConvertInvoice` + recompute tax, save `fx_conversion`. Missing rate ⇒ fail session creation. Tests: converted draft has INR `amount_due`; payment record inherits INR.

### Task 2 — Convert in the one-off checkout path
`startCheckoutOnOneOffInvoice`: convert between `ComputeInvoice` and `StartPayFirstCheckoutSession`. Same guard + tests.

### Task 3 — Billing-currency change blocked during open checkout (§8.2)
Add a customer-scoped active-checkout lookup and reject the billing-currency change with a clear error while a session is open. Test with an open session present/absent.

### Task 4 — Freeze converted checkout draft (§8.4)
Reject recompute + manual line edits on a converted checkout draft (void still allowed). Test.

### Task 5 — End-to-end pay-first
Session create → converted INR link → pay INR → finalize skips conversion → amounts unchanged. Test both entry paths + the auto-finalize path.
